## そもそもPHPって何？

**ウェブサイトの裏側を動かしている言葉**のひとつです。

ページを見ているだけだと見えませんが、**裏で働いている**イメージです。

| | |
|---|---|
| 🏪 お店のサイトで**営業時間が表示される** | 裏で情報を取ってきている |
| 📝 **問い合わせフォームを送信する** | 裏で受け取って、送っている |
| 👤 **会員ページにログインする** | 裏で「この人は本人か」を確かめている |
| 🔍 **サイト内で検索する** | 裏で探して、結果を出している |

この**裏側の仕事をしているのがPHP**、ということになります。

### どんなところで使われているのか

**思ってるよりも結構身近な存在でした。**

| 📰 ニュースサイト・メディア | 同上 |

| 🛒 ネットショップ | PHPで動いているものが多い |
| 📚 **ウィキペディア** | PHPで動いている |

**WordPressは世界で一番使われているサイト作成の仕組み**で、  

**それがPHPで動いています。**

つまり、**普段見ているサイトのかなりの数がPHPで動いている**ということになります。

|---|---|

## 今回は何が起きたの？

2026年10月21日、**PHPの公式から2件の脆弱性が発表されて、修正版が公開されました。**

| | |
|---|---|
| **呼び名** | **php2shell** |
| 番号 | CVE-2026-109618／CVE-2026-109619 |
| **深刻度** | **9.2（10点満点で、かなり高い）** |
| 何が起きうるか | **外から、勝手にプログラムを動かされる恐れ** |

WordPressなどの構成でも再現したという報告が出ていて、  

**対象が広い**のが今回の特徴でした。

**修正版はこちらです。**

| | |
|---|---|
| PHP 8.5系 | **8.5.12** |
| PHP 8.4系 | **8.4.27** |
| **PHP 8.3系** | **8.3.36** |
| PHP 8.2系 | **8.2.35** |

⚠️ **PHP 8.1以前には、公式の修正版がありません。**  

OSやサーバー会社が出す独自の修正に頼ることになります。

### なぜ騒ぎが大きくなったのか

ニュースを追っていると、**中身とは別のところでも話題に。**

- 🤖 **AIを使った調査で見つかった**脆弱性だった
- 📢 **公開前に番号がSNSに流れてしまい**、PHP側が発表を前倒しした
- 🚨 その流出時に**深刻度が誤って表示**されていて、さらに広まった

## 会社のサイトが狙われると、どうなるのか

**自分でサイトを持っていない人にとっては、ここからが本題**だと思います。

PHPは、**会社のサイトやサービスでも広く使われています。**

| | |
|---|---|
| 🛒 ネットショップ | 会員情報・購入履歴・住所 |
| 📅 予約サイト | 名前・電話番号・来店履歴 |
| 👤 会員向けページ | ログイン情報 |
| 📨 問い合わせフォーム | 送信された内容 |

個人のブログが狙われても、被害はその人の範囲で止まります。

ところが**会社のサイトだと、お客さんの情報がまとめて置いてある**ので、入られたときの影響がまったく違います。

{{< voice c="maoneko" side="right" >}}規模がちゃうんよな{{< /voice >}}

### 使っている側に何が起きる？

**ここが一番大事なところだと思います。**

自分が会員になっているサイトが狙われた場合、起きるのはこういうことです。

| | |
|---|---|
| 📇 **登録した情報が漏れる** | 名前・住所・電話番号・メールアドレス |
| 🔑 **ログイン情報が漏れる** | IDとパスワードの組み合わせ |
| 💳 **支払い情報** | サイトによってはカード情報も |
| 🛑 **サービスが使えなくなる** | 復旧までログインできないことがある |

とくに怖いのが**2つ目**でした。

**同じパスワードを他のサイトでも使っていると、そっちまで入られる**からです。  

漏れたIDとパスワードを、片っ端から他のサイトで試す、ということが実際に行われています。

{{< voice c="maoneko" side="right" >}}使い回してたら、1か所漏れただけで全部やられるんか{{< /voice >}}

{{< voice c="chapio" side="left" >}}そうです。だからパスワードは分けておきたいんです{{< /voice >}}

### 利用者側にできること

サイトの中身は直せませんが、**備えはできます。**

- 🔑 **パスワードを使い回さない**（これが一番大きい）
- 🛡️ **二段階認証を設定しておく**（パスワードが漏れても、すぐには入られない）
- 📢 **お知らせが来たら、落ち着いて読む**
- 💳 **カードの明細を、たまに見る**

⚠️ あわせて気をつけたいのが、  

**こういう騒ぎのあとに届く「ご確認ください」系のメール**。  

**不安につけこんだ偽メールが増える**ので、  

**メールのリンクからではなく、いつも使っているアプリや公式サイトから入る**ほうが安全です。

## ここからは、サイトを持っている人の話

自分でブログやサイトを運営している場合は、**直す側**になります。

とはいえ、**全部を自分でやるわけではありませんでした。**

### 更新するのは、自分とは限らない

**契約の形によって、PHPを更新する人が違います。**

| | 誰が更新するか |
|---|---|
| **共用レンタルサーバー・ブログサービス** | **運営元がやってくれる** |
| VPS・専用サーバー・自分で管理している場合 | **自分でやる** |

よくある「月額数百円〜千円くらいのレンタルサーバー」は、たいてい**前者**です。

その場合、**自分でサーバーの設定をいじる必要はありません**。

{{< voice c="chapio" side="left" >}}焦って自分でサーバー設定を変えないでください{{< /voice >}}

{{< voice c="maoneko" side="right" >}}そこは触らんほうがええんや{{< /voice >}}

⚠️ ただし**契約プランやサービスによって範囲は違う**ので、  

**自分がどっちなのかは確認が必要**です。

## まとめ

- **PHP**はウェブサイトを動かしている言語。**WordPressもPHP製**
- 今回の脆弱性は**php2shell**。**深刻度9.2**とかなり高い
- 修正版は **8.5.12／8.4.27／8.3.36／8.2.35**
- **PHP 8.1以前は公式の修正版がない**ので、使っている場合は要確認
- **自分のパソコンを消しても意味がない**。狙われるのはサーバー
- **共用レンタルサーバーなら、更新するのは運営元**
- 個人は**お知らせの確認**と、**WordPress本体・テーマ・プラグインの更新**
- **静的サイトはPHPを使っていないので対象外**
- 分からなければ**サポートに聞く**のが早い
- **企業のサイトが狙われると、利用者の情報が漏れることがある**
- 利用者側の備えは**パスワードを使い回さない**ことと**二段階認証**
- 情報漏えいは**会社の業績や配当にも響く**

ニュースを見たとき、最初は「難しそうやから後で」と思いました。

ただ、**自分のブログが対象かどうかを調べるだけ**なら、そんなに時間はかかりませんでした。
